# Clavis Treatment Plan PDF Service

A standalone HTML/CSS → PDF renderer for Clavis. It accepts a JSON-compatible payload,
renders an A4 treatment plan using Jinja2 + WeasyPrint, and can PUT the generated PDF
to an S3 presigned URL. No web server and no AWS credentials are required by the renderer.

## What's included

- `templates/treatment_plan.html` — editable Jinja2 HTML template
- `static/treatment-plan.css` — print-focused styles, palette, table layout, page furniture
- `static/assets/brand/clavis-logo.svg` — editable vector brand mark
- `static/assets/icons/*.svg` — standalone vector icons used by the template
- `static/assets/fonts/Inter-*.otf` — bundled Inter font weights for consistent typography
- `renderer.py` — render-to-bytes, render-to-file CLI, and presigned S3 upload
- `lambda_handler.py` — AWS Lambda entry point
- `Dockerfile` — Lambda container image with WeasyPrint system libraries
- `examples/sample.json` — illustrative sample payload

## Run locally

WeasyPrint needs native libraries in addition to Python dependencies. Follow the
installation guide for your OS: https://doc.courtbouillon.org/weasyprint/stable/first_steps.html

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1

pip install -r requirements.txt
python renderer.py examples/sample.json --output sample.pdf
```

The included Dockerfile targets AWS Lambda's Python 3.12 container base and installs
native dependencies using DNF. Build and run/test it in the same architecture you plan
to deploy. Confirm the exact native package names and WeasyPrint runtime compatibility
in your deployment region/base image before production release.

## Upload using an S3 presigned PUT URL

The presigned URL must be generated by your trusted backend for the **PUT** operation.
If the URL was signed with a specific `Content-Type`, send exactly that content type.

```bash
python renderer.py examples/sample.json \
  --presigned-url "https://your-presigned-put-url"
```

Or from application code:

```python
from renderer import load_json, render_and_upload

payload = load_json("examples/sample.json")
result = render_and_upload(payload, presigned_url)
print(result)  # safe metadata only; does not include the URL or patient details
```

A presigned URL is a bearer credential: never log it, put it in analytics, or expose it
to the browser unnecessarily. Generate it for the exact object key and short expiry you
need. If the URL is signed with `Content-Type: application/pdf`, keep that header unchanged.

## Invoke as Lambda

Package this folder into a container image and push it to ECR. Set the Lambda handler
to `lambda_handler.handler` (the Dockerfile already does this).

Expected event:

```json
{
  "payload": {
    "doctor": {},
    "clinic": {},
    "patient": {"name": "Example Patient"},
    "plan": {}
  },
  "presigned_url": "https://..."
}
```

The handler returns metadata only; the PDF is uploaded directly to S3. It doesn't return
PDF bytes or echo the presigned URL.

## JSON contract

Top-level keys:

- `doctor`: name, credentials, registration_number, phone, email
- `clinic`: name, address, phone, email
- `patient`: name (required), id, age, gender, phone
- `plan`: id, date, title, subtitle, diagnoses, lab_results, lab_summary, medications,
  medication_notice, dietary_recommendations, lifestyle_steps, next_appointment,
  additional_tests, notes, signature, references, disclaimer

Unknown keys are ignored by the template. Lists may be empty or omitted. Use ISO dates
in your internal contract and format them for display before rendering, or provide
already-formatted display values as in the sample. For stricter validation, introduce
a JSON Schema/Pydantic contract at the service boundary.

## Customization

- Colors: edit CSS variables at the top of `static/treatment-plan.css`.
- Layout and wording: edit `templates/treatment_plan.html`.
- Optional sections: Jinja `{% if ... %}` blocks already omit empty sections.
- Pagination: tables repeat their header; table rows and selected panels avoid splitting.
  Long content can flow onto additional pages. Always regression-test unusually long
  medication names, notes, and lab tables because print engines have layout limits.
- Icons are inline SVG in the template, so they don't require external assets.
- No Tailwind or client-side JavaScript is needed for static PDF generation. All fonts, icons, and the logo are bundled locally; the renderer does not need external asset requests.

## Production security and reliability checklist

1. Keep the Lambda private and invoke it from your backend with IAM permissions.
2. Validate payload sizes and allowed section lengths before rendering.
3. Do not accept arbitrary HTML, CSS, file paths, or external URLs from payload data.
4. Keep external network access unavailable to the renderer where practical. Bundle fonts
   and images locally. Never render untrusted HTML.
5. Don't log payloads, presigned URLs, patient identifiers, or clinical notes.
6. Configure memory and timeout after measuring representative documents.
7. Set concurrency limits and alarms; track render duration, failure count, and PDF size.
8. Test the built image in Lambda-compatible Linux and architecture before deployment.
9. Verify uploaded PDF size and content type from the backend where appropriate.
10. This is a document-generation component, not a clinical decision system. Validate all
    medical content upstream and have clinicians review generated output.

## Important pagination note

This is a practical starting template, not a guarantee that every payload produces exactly
the same page count. Content is allowed to expand across pages. Test short, typical, and
very long payloads in the actual target runtime before shipping.


## Brand and icon assets
The exact logo supplied for Clavis is included at `static/assets/brand/clavis-logo.png`.
The untouched uploaded source is retained as `clavis-logo-source.png`. The lifestyle
runner and next-step checklist are independent SVG assets under `static/assets/icons/`
and are referenced from the Jinja template rather than embedded inline.
